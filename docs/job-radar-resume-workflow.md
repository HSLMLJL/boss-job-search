# 从岗位 JD 到简历准备与投递跟进

如果你的需求是“我想找工作，但不知道哪些岗位值得投、简历该针对什么要求写”，Job Radar 能先帮你建立一份带岗位信息和可选完整 JD 的求职清单。**它目前不内置简历导入、AI 匹配评分、简历改写或面试题生成。** 下面的对比和改写由你完成，也可以自行使用熟悉的 AI 工具辅助。

## 先收集足够判断的岗位资料

1. 用自己愿意考虑的职位名称搜索。相近叫法可以分别填，例如“用户运营、内容运营、社区运营”；产品、数据、开发、设计、销售等方向都可换成自己的词。
2. 选城市和必要条件，用“初筛后补 JD”。缺失信息先保留，避免把没有写清的条件当成不满足。
3. 导出时勾选：岗位名称、公司、城市、薪资、经验、学历、完整 JD、岗位链接、JD 采集状态、筛选依据、我的进度、我的备注。
4. 只对“已采集”且正文非空的 JD 做完整要求分析；待补或空正文的岗位先回原链接阅读。筛选通过仅表示符合已设置的规则，不代表你的履历已匹配。

## 对照真实经历，决定先投哪些

先选少量值得考虑的岗位，逐条阅读 JD，将下面几项填入备注或自己的表格：

| 对比项 | 你要确认什么 |
| --- | --- |
| 工作内容 | 实际负责什么业务、解决什么问题，是否是自己想做的方向 |
| 必要条件 | 城市、经验、学历和明确硬性条件是否满足；未写明的条件另行确认 |
| 经历证据 | 简历中哪段真实工作或项目能够证明相关能力 |
| 待补信息 | 有能力但没写清，还是尚无对应经历；两者分开记录 |
| 下一步 | 调整哪一段简历、回岗位页核对哪件事、是否值得投递 |

不要因为列表中出现了“AI”“SQL”等词，就认定这是合适的岗位。完整 JD、实际业务、个人偏好和履历证据需要一起判断。

## 按 JD 调整简历表达

从已有的真实经历中选择最相关的证据，调整摘要、项目排序和描述重点。保留事实、日期、职责和成果口径；JD 中出现但你没有的技能，不应直接补进简历。

如果选择使用外部 AI，可手动提供你愿意分享的简历内容与目标 JD，并参考这段提示词：

```text
请根据下面的目标岗位 JD 和我的真实简历，帮助我准备针对性投递材料。
先列出岗位要求，再逐项对应简历中的证据，区分“已有证据”“表达不清”“缺少证据”。
每项判断引用提供的原文，不把 JD 中的要求当成我已有的经历。
给出应该优先调整的简历段落及修改建议；不得补造公司、职责、技能、数字或成果。
对不确定之处列出需要我回答的问题。最后列出值得为面试准备的三个经历追问。
目标 JD：……
真实简历：……
```

这是一段手动工作方法，不是 Job Radar 内的自动分析功能。项目不会自动把你的岗位表或简历发送给外部 AI；是否使用其他服务、分享哪些内容，由你决定。

## 投递后保留上下文

在 BOSS 原页面由你确认并投递，随后回到工作台标为“已投”。备注中可记录投递日期、使用的简历版本、沟通结论和待办。面试前再回看原 JD 和这些记录，避免只凭岗位名称准备。

下一轮搜索可以复用模板。相同岗位再次出现时会继承个人状态和备注；“首次收录”是本地首次看到的时间，不等于招聘发布时间。“已投”“面试”等状态需要你手动维护，当前没有自动提醒或平台状态同步。
